# 模型接入与任务交流

## 两种连接

- 网页和 Android App 连接本机助手服务。推荐使用 Tailscale HTTPS 地址，并在电脑生成连接配置，手机一次导入。具体步骤见 [手机首次连接](phone-connection.md)。
- C++ 服务连接云端模型。在电脑网页管理供应商，App 不保存模型密钥。

## 配置模型

1. 电脑网页进入“连接与授权 → 模型供应商 → 添加供应商”。
2. 填写名称、API Key、API 请求地址；地址可为基础地址（例如 `https://api.openai.com/v1`）或完整的 `/responses`、`/chat/completions` 请求地址，后缀会自动识别。支持 HTTP 和 HTTPS；HTTP 会明文传输 API Key 和资料，建议优先使用 HTTPS。此设置仅用于模型 API，手机连接助手仍使用 HTTPS。
3. 点击“获取可用模型”，在“模型 ID”选择服务商返回的模型；列表不可用时可手动填写。列表成功不代表聊天生成已验证，Sol / Luna 等产品昵称也不一定是真实 API ID。
4. 默认自动估算预算，不需要填写单价。只有需要更换接口类型或按服务商报价计算时，才展开“高级设置（可选）”；选择“手动报价”后可填写输入和输出单价。
5. 点击“保存并使用”，立即对新调用生效，无需编辑文件或重启服务。也可“仅保存”后在列表切换。密钥输入框为密码框，编辑时留空保留；改地址时必须重新输入密钥。
6. 返回聊天发送一条消息，核对真实回复和用量。已有阻塞消息使用“继续原消息”；结果未知的收费调用仍需核查并明确批准重试。

供应商的名称、地址与模型保存在私人 SQLite 数据库，密钥单独加密存储且不进入同步、事件、聊天或公开配置。在 Windows 使用当前用户 DPAPI；迁移到不同 Windows 用户或机器时需重新填写密钥。在 Linux/WSL 使用 OpenSSL AES-256-GCM，主密钥 `provider-master.key` 必须为当前用户所有且权限 0600，迁移时需单独保护与恢复此文件。私有备份仍不得公开。

供应商管理接口只接受电脑管理令牌；设备令牌和 worker 不能管理供应商。切换或编辑不改变已经发出的模型请求及其预算计价。当前支持 Responses / Chat Completions 的文本请求，不代表工具调用、流式聊天或所有第三方扩展都已支持。

界面行为参考 [CC Switch 供应商表单](https://github.com/farion1231/cc-switch/blob/main/src/components/providers/forms/ProviderForm.tsx)；模型列表使用 [OpenAI List Models](https://developers.openai.com/api/reference/resources/models/methods/list) 的标准格式。

## 费用估算

未填写报价时，使用本地预算参考标准：输入 $10、输出 $50 / 百万 token。这是产品的估算参数，不是任何模型或供应商的报价，也不会根据 Sol/Luna 等名称猜测真实价格。网页显示“预算估算与预留”，调用记录标注 `cost_basis=estimate` 并保存当时采用的参考费率；API 返回的 token 用量用于结算估算。未知用量或调用结果保留原预留，不能按免费记账或自动重试。

估算仍执行每周预算阈值检查，但实际账单可能高于或低于估算；本地阈值不保证供应商实际扣费的上限。需要严格控制实际扣费时，在供应商账户设置额度，或使用核实过的手动报价。当前没有接入供应商余额/账单查询，也没有自动获取真实报价。

已有完整手动报价保持原计价；编辑名称或密钥不会改变计价。更换地址或模型时，清除旧报价并恢复自动估算，避免误用另一个模型的费用。已发出的请求保留原计价快照，修改设置只影响下一次调用。

## 保留旧环境变量配置

已有部署仍可在 `local.json` 顶层配置 `provider`；`provider_example` 不参与调用。没有在页面选择供应商前，服务沿用旧配置。

```json
"provider": {
  "base_url": "https://api.openai.com/v1",
  "protocol": "responses",
  "model": "YOUR_ACTUAL_MODEL_ID",
  "api_key_env": "PA_API_KEY",
  "max_output_tokens": 3000
}
```

这是需要补齐后嵌入配置文件的片段。省略价格时自动估算；已有完整数字价格按原报价计算。也可显式设置 `pricing_mode` 为 `estimate` 或 `custom`；`custom` 必须同时提供非负数字 `input_usd_per_million` 和 `output_usd_per_million`，单位为美元/百万 token。模型必须是该 API 账号实际可调用的 ID，不能直接用聊天产品中的 Sol/Luna 昵称。

`responses` 会向 `base_url` 追加 `/responses`；`chat_completions` 会追加 `/chat/completions`。因此不要在 `base_url` 里重复填写这些后缀。目前仅支持这两个协议的文本结果，不代表支持任意兼容接口、工具调用或流式聊天。

在准备启动服务的 PowerShell 中通过隐藏输入加载密钥，避免把密钥写进命令历史：

```powershell
# 在当前版本的项目目录执行；stop.ps1 仅识别 start.ps1 启动的同目录工作区。
./tools/stop.ps1 -Data '你的私人工作区绝对路径'
$modelSecret = Read-Host '模型 API Key' -AsSecureString
$modelCredential = [System.Net.NetworkCredential]::new('', $modelSecret)
$env:PA_API_KEY = $modelCredential.Password
$modelCredential = $null
$modelSecret = $null
./tools/start.ps1 -Data '你的私人工作区绝对路径' -Browser
Remove-Item Env:PA_API_KEY
```

密钥会由新服务继承；从当前终端移除不会清除已经运行的服务中的密钥。配置和环境变量都在启动时加载，修改后必须重启对应服务。不要把 `local.json`、令牌或密钥提交进公开 Git，也不要将密钥粘贴到助手聊天中。

模型状态不证明密钥、价格或模型真实可用。接入后，用少量已授权的测试资料发起任务，核对草稿、原文引用和费用记录，才算完成真实联调。网络中断导致调用结果待核实时，先核查供应商记录，不要直接重复调用。

## 从使用引导开始

网页和 App 的“使用引导”依次说明连接工作区、接入模型、授权资料和开始聊天。工作台也提供“开始聊天”和“如何开始使用”入口。首次使用不需要先了解所有页面。

## 连续聊天与发起任务

在“聊天”新建或选择对话，输入目标、问题或新功能想法。每条消息与回复保存在本机 SQLite，网页和手机同步查看。后续回复会读取该对话按顺序保存的前文；不同对话不会互相混入。聊天只进行讨论，不会自行联网搜索、执行代码或批准外部操作。

电脑网页支持 Enter 或 Ctrl+Enter 发送（Mac 也可用 Cmd+Enter），Shift+Enter 换行；输入法选词、空白输入和等待上一轮处理时不会发送。手机触屏网页的普通 Enter 保留换行，仍可点击发送或使用 Ctrl/Cmd+Enter。

讨论明确后，选择“创建调查任务”，核对具体目标、链接和关联资料。任务保存创建时的对话快照，后续聊天不会悄悄改变已提交任务。可在任务、草稿和表格查看结果。

选择“保存功能需求”会保留目标、验收要求与对话快照，进入待开发列表。当前尚未接入自动代码执行器，不会因为聊天中说“实现它”就直接修改程序。新代码仍需针对性验证、两名独立 Agent 审查、用户确认后启用。

聊天中发送的文字及同一对话历史会交给配置的云端模型；不要输入密钥。普通文件仍走资料授权。聊天不会自动检索全盘文件或导入微信、QQ 记录。对话历史最多 120 KB，超过时明确要求新建对话，旧记录保留，不静默裁掉前文。当前没有流式逐字显示，回复完成后同步展示；不完整回复会标明。

手机离线时可以看缓存聊天、保存输入并暂存一条待发送消息；同一对话的上一轮尚未结束时，等待回复或处理阻塞后再发送。两端同时发消息发生顺序冲突时，保留手机原消息，查看最新对话后可以明确选择重新发送。网络结果不明时沿用原请求标识对账，不能当作新消息盲目重发。

没有模型配置时，消息照常保存在工作区，回复等待配置。在页面配置并使用模型后，选择“继续原消息”。付费调用结果不明时，需先在任务页核查并明确批准重试，原费用预留保留。

## 也可以直接创建任务

1. 在网页或 App 的“工作台 / 任务”选择“＋ 新任务”，用自然语言写期望结果，附上链接并选择关联资料。
2. 私人资料需先授权云端使用；本地索引不等于同意发送给模型。未接入模型时任务可能等待配置，草稿和本地资料仍可管理。
3. 任务等待补充或被阻塞时，使用“补充并继续”回复。输出在草稿、表格和任务结果中查看；已完成任务若要开展后续调查，目前需要新建任务并关联所需资料。

直接创建的旧式任务补充框仍只保存最近一次补充；需要连续交流时请使用聊天页。离线暂存不会在本机服务不可达时调用模型。

连续对话由本机保存并在调用时提供上下文，参考 [OpenAI 官方对话状态说明](https://developers.openai.com/api/docs/guides/conversation-state)。当前保存文本对话，不依赖供应商侧的 conversation ID。
